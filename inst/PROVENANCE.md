# Provenance of spatialLagGLM

This file documents how AI tools and third-party code were used in this
package, as required by the Bioconductor AI and third-party code policy.

## AI assistance

| Tool | Used for |
|---|---|
| Google Gemini | Original package: R and C++ code, tests, documentation, vignette and README (as `spatialDESeq`). |
| Claude (Anthropic) | Revision in response to the Bioconductor review: renaming to `spatialLagGLM`; per-sample sparse weights; argument validation; `assay.type` and `size.factors`; failed-fit reporting; the `spatial_lag` plot metric; new unit tests; rewritten vignette, README and DESCRIPTION; review reply. |

Files with substantial AI assistance carry a provenance comment at the top
(all files in `R/`, `src/rcpp_spatial_map.cpp`, `tests/` and the vignette).
`R/RcppExports.R` and `src/RcppExports.cpp` are generated by
`Rcpp::compileAttributes()`.

## Review and testing

The code was first generated with Google Gemini and revised with Claude in
response to the Bioconductor review. I checked the result as follows:

- I ran the unit tests (55 pass), built the package and the vignette, and ran
  `R CMD check --as-cran` and `BiocCheck` locally.
- I ran the example analysis on the simulated data and on the STexampleData
  Visium example, and looked at the outputs and plots.
- I read the R code in `R/spatialLagGLM.R` and the model description in the
  vignette, and I understand that the model regresses a gene on the spatial
  lag of its own counts, that it is not a SAR model, and that the p-values
  are exploratory.

The package was tested with the unit tests in `tests/testthat/`, the vignette
(simulated data and the STexampleData Visium example), `R CMD check
--as-cran` and `BiocCheck`.

## Third-party code

No third-party source code is bundled. The package depends on CRAN and
Bioconductor packages declared in `DESCRIPTION` (including Rcpp and
RcppArmadillo for the C++ code). The package license is MIT.
